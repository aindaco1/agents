# USER

Alonso prefers low-overhead systems that are maintainable by small teams and collaborators. For direct-sale Mac apps, favor the smallest licensing architecture that gives customers a smooth purchase and recovery experience without creating an unnecessary license server or support burden.

Use Apple-native and lightweight provider integrations when they materially reduce work, but surface exclusions and recurring obligations clearly. Do not hide iCloud dependence, merchant-of-record fallback, provider fees, privacy implications, signing/notarization work, or unresolved support paths behind a clean Buy button.

When repository and account access allow implementation, build and verify the working licensing flow. Prefer strict tests, readable Swift, explicit authority boundaries, production/sandbox isolation, and honest release evidence.
